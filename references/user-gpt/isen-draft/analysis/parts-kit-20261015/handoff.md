# 低コストモデルへの引継ぎ仕様

2026-10-15。仮ゴールは「下位モデルが設計を再解釈せず、限定した作業を引き継げる状態」。この文書は部品制作の入出力仕様であり、現在情報を集約する新台帳ではない。全体の再開位置はcompany-data/handoff-ledger.md。

## 今回の判断を固定する

対象は追加GPT原画6面（印刷番号17・19・20・21・22・23）と、外国人の仲間の多さを主訴求にする任意の見開き2ページ。原画の構成意図を読み、現状の冊子との整合をとり、実写真を使うパーツから再構成する。完成冊子の撮影画像や紙の遠近・影・湾曲を出力紙面として貼らない。原画は残す。

ユーザーが指定した2パターンは「外国人の仲間を強調する2ページを足す／引く」。実写真/デジタルは素材表現の別軸、HAL/医専はテイストの別軸。2パターンの意味を勝手に置き換えない。日本人学生は現在0人（ユーザー申告）。日本人の友人を求める保護者の希望を、現在の学校実績や保証へ変えない。

原画のnear100%指定は、主従・写真と文字の大小・情報群・密度の比較根拠として維持する。今回の実写真化と正確な情報への整合に必要な差は別記し、無断の短文化・余白拡大・装飾追加をしない。テイストによる造形変更は上位担当が指示した部品差分だけ。

## 既存構成をそのまま使う

- `company-data/photos/`：実写真の唯一の正本。79点登録・実体あり。複写・再登録しない。
- `shared/generated-assets/`：生成のビジュアル。既存57点はGPT原画由来。実写真へ付け替えない。モックアップのまま最終紙面へ貼らない。
- `shared/components/`：既存photo-frame/section-heading/stat-card/qr-block/folioを再利用し、不足だけbrochure-kitへ追加。
- `shared/layouts/brochure-kit.css`：名前空間を限定した部品と2テーマの構造差分。既存CSSは上書きしない。
- `references/user-gpt/isen-draft/`：原画と分析。ファイル番号と紙面番号は違う。18面は未提供。
- `books/`：最終配置は後段。今回は新BOOK・冊子PDF・ページ順を実装しない。

## 判断の分担

| 低コストモデルへ渡せる | 上位担当に残す |
|---|---|
| 固定APIのHBS/CSS実装、指定IDの参照、寸法/リンク/コンパイル確認、指定ケースの表示確認 | 学校情報の採否、写真選定と意味、トリム採否、テイストの造形判断、必要パーツの追加削除 |
| 指定ケースに対する欠損・切れ・データ欠落の報告 | 読者への訴求、構成意図、参照への忠実度、見開きの採用と掲載位置 |
| 技術結果をpass/fail/uninspectedに分けて返す | 独立した目視審査と提出判断、事実/権利の承認 |

対象の小型モデル名や切替はまだ指定していない。名前や費用を推測せず、最初はjobs.yamlのL01を1件だけ渡す。その結果を上位担当が採点してから同種の作業を広げる。

分担の参考は [OpenAI公式の費用最適化](https://developers.openai.com/api/docs/guides/cost-optimization)。モデルを小さくしただけで品質が維持されるとは判断せず、今回の指定ケースと独立確認で実作業を評価する。

## 未確認の扱い

2028費用・日程・出願書類・AO減免、具体的な補習/生活/就職支援、施設、取材コメント等は不足。原画の数字には不整合がある。低コストモデルは空欄を埋めたり2027正本を2028へ読み替えたりしない。教材用のダミー原稿だけで部品の動作を確認する。学校の事実は必ずcompany-data正本の参照を上位担当が指示する。

実写真のAI入力禁止。写っている人の国籍・友人関係・役職を推定しない。受付写真をAO面接や保護者相談と説明しない。公園を校庭・キャンパスと説明しない。学生コメント・施設写真が足りなければ不足を返す。写真候補は `photo-candidates.yaml` に条件と制限を記載。

## 着手済みと引継ぎ前の確認

実装済みはicon/info-card/flow/data-table/speechの5部品と、共通CSS・HAL/医専の構造例。部品APIは `shared/components/brochure-kit/README.md` に固定した。支払timelineとflowは別で、時系列/金額の仕様を低モデルに発明させない。

`npx tsx shared/components/brochure-kit/verify.ts` で既存の厳格エンジンによる26ケースを描画する。このコマンドの出力は `.cache/parts-kit-20261015/compile-check.json` と `preview.html`。確認HTMLで2テーマ・写真参照・最低入力・表・6手順・6アイコンを実見し、画像パスと所見を返す。これらとコマンド結果を親が統合した記録が本フォルダーの `verification.json` であり、verify.tsの自動出力ではない。未実施の冊子配置・印刷適合・読者テストを合格扱いしない。

## 実装者へ最初に渡す文

「DTPルートでAGENTS.md、.agents/skills/dtp-parts/SKILL.md、本handoff.md、jobs.yaml、brochure-kit/README.mdを読んでL01だけ実施してください。先に許可ファイルと入力契約を復唱し、その範囲だけ実装します。学校情報・写真・テイスト・BOOKを変更しません。曖昧な点は推測せず返し、コマンド結果と画像を返します。Git保存・独立審査は親が行います。」

この文を読んで意図理解からやり直す必要が出る、追加デザイン判断が必要になる、正本や共通エンジンに変更が及ぶ場合は、低コストモデルの担当範囲を超えているため上位へ返す。
