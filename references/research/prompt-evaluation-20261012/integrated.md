# 全候補比較の統合

対象は技術解説5件除外後の指示原文14ファイル。Taste本体とTaste Redesignにそれぞれ同一本文2ファイルがあり、SHAとバイト一致を確認、独自本文は12種類。制作・編集長・独立レビュアー・パーツの4サブが各々全件を全文確認。親は対象集合・読了記録・SHA一致と根拠箇所を照合して統合した。人気指標を評価軸にしていない。

## 提案の変更

制作と密度判断の中心はImpeccable Layout。主従・情報のまとまり・疎密・領域ごとの情報量を明示し、画像やソースの証拠で検査する。機械検査の無指摘を階層とリズムの合格へ読み替えない。

編集長の判断手順はImpeccable Critique。視覚評価と技術評価を隔離し、各証拠の一致・不一致を統合する。レビュアーの視覚判断へ先に技術合格を渡して誘導しない。

Frontend Designは依頼との制作前照合、定型案の点検、画像自己批評。Visual Storytellerは写真方針、全体の流れ、情報階層を編集する補助。Image Prompt Engineerはパーツ制作。Bolderは既存の視覚世界を守って弱い面を強める局所改善。

## 原文根拠

Layoutの18–22行は主従・意味のまとまり・疎密・構造・密度を評価対象にする。31行は技術スキャンの無指摘で主従/リズムを証明できないとする。35–41行は制作前に主役、密度と間隔のリズムを決め、72行はyesだけを検証の代わりにしないとする。

Critiqueの7–11行と33–35行は視覚評価と機械検査の隔離、104行は単純連結ではなく証拠統合を求める。Frontendの45行は依頼の言葉優先、53行は制作前の依頼照合、59行は画像自己批評。Storytellerの30/55/65/67行は写真方針・視覚ペース・図解・情報階層。

Taste本体9行は全規則が文脈依存で自動適用しないと明記している。一方、327–330行の架空精密値禁止と640行のmessy data推奨は同居しており、自社確定事実へ転用しない。Redesign58/82/88/146行の余白倍増/架空らしい端数/日付ランダム化/余白最大化も原文中の指示であり、人間が要求した内容ではない。
