# 素材検査と通常制作の両立：実施計画

2026-10-22。ユーザーが目的条件の検証結果を踏まえ実装を指示。

## 維持する条件

- 資料ID・原本/加工版の役割・SHA・サイズ・形式・欠損・LFS実体・未登録検出を維持する。
- GitHubの必須 `asset-integrity`、最新mainとの同期、違反時のマージ拒否を維持する。
- 保存済み版を現在入力から生成した最新版として取得させない。
- 実使用の入力変更・入力追加削除・CSS/フォント・描画中の変更は最新版の検査で検出する。
- 未使用候補の追加で無関係な全冊子を古くしない。正規の記録同期を無関係な出力の鮮度で止めない。
- 既存パンフレット/募集要項/OC原本の画像・PDF・文章・料金・QRの実体は変更しない。別途指示のOC5点修正は別の確認版として保存する。HALの再制作はしない。

## 手順と完了条件

1. [x] 保全：現行配布PDF・表紙1/2・本文のSHAを記録。既存失敗を記録。
2. [x] 保存状態：明示的な保存版を導入。専用経路で理由と実体を確認して保存状態へ移し、通常getは拒否、`--saved`のみ取得可。古い証拠を新しい描画証拠に書換えない。
3. [x] 同期経路：baseline同期では実体/スキーマ/権利/禁止語等を検査し、出力鮮度だけは独立させる。通常のasset:checkでは現行出力の鮮度を引き続き拒否。
4. [x] 依存採取：今後の標準再描画はBOOK設定・実使用の共有素材/partial/CSS/font・正本・描画コードを採取。追加参照も検出。依存一覧を変更前後で再採取し、不一致なら登録拒否。
5. [x] 移行：旧来の広い入力集合を現入力へ書換えて最新と偽装しない。保管対象は保存状態へ移行し、取得先も保存版であることを明示。日本人版の固定アダプター出力も保存物として正確に分類。
6. [x] 検証：未使用追加は通る/実使用変更は止まる、保存版の最新版取得は止まる/保存取得は通る、欠損/役割違い/未登録は止まる、正規同期は通る/内容不正は止まる、描画中変更は止まる、を対で検証。親が統合しサブが独立レビュー。
7. [ ] 統合（ローカル検証・保全照合・記録同期は完了。push/必須CI/通常マージの実結果はPR #62で確認）：型検査・対象試験・全体検査・保全SHA照合。記録と運用説明を更新しpush。承認済みPR #62は必須検査通過後に通常マージする。保護を回避しない。
