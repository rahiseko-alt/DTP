# 両エージェント共通の情報取得

CodexもClaude Codeも、開始・事実回答・編集・マージ提案の直前にリポジトリルートで実行する。

```bash
python3 system/scripts/sync-context.py
```

成功後に `.cache/session-context/manifest.json` のSHA・時刻・状態を確認し、`.cache/session-context/context.md` を読む。必要な箇所に分けて全文を読む。コマンドが成功しても内容を読まなければ確認したことにはならない。常駐サービス、追加トークン、Chromiumは不要。

取得するのは最新mainの固定SHAにある正本・共通現況・両担当ノート・共通指示。作業checkoutは切り替えず、未保存変更も上書きしない。生成ファイルは無視済みの.cacheに保存し、GitHubへコミットしない。失敗・offline時は最新確認済みとは言わず、事実を必要とする編集を進めない。

## 読む順序と判断

1. `docs/coordination/current.yaml` の現在判断・所在・限界を読む。
2. 学校の事実は `company-data` の正本を読む。現況は参照索引であり事実値の別正本ではない。
3. 両担当のノートを読み、後続の訂正と根拠を確認。古い「未確認」を後の登録済み情報より優先しない。
4. 関連BOOK・原本を読む。別ブランチが必要なら該当refを取得してSHAを表示し、未マージであることを明記する。

「原本あり」「他担当が確認済み」「正本登録済み」「今回の採用待ち」「実際の不足」を分ける。自分が原本を再読していないことを材料不足とは呼ばない。参照に矛盾があれば具体的なファイル・事項を示して解決する。初回のmainに現況ファイルが無い場合は、取得結果がfreshでも共通現況は未整備である。

## 更新とマージ

学校正本・素材・判断が変わるPRでは、担当が共通現況の該当項目・根拠・適用限界を同じPRで更新する。相手のノートは更新しない。共通現況は新しい共通ノートではなく現在状態の索引。履歴は既存の担当ノートとGitに残す。

開始時の人間の訂正は自分のノートと共通現況に記録し、マージまで未マージと扱う。マージ承認は従来どおり人間の明示指示を要する。pushだけをmain反映と呼ばない。マージ後は再取得して双方の入口から同じmain SHAと更新内容を確認する。

この手順を両担当の各環境で実行する。別環境の起動・ログイン・既読・常駐実行をこのチャットから自動化したとは主張しない。
