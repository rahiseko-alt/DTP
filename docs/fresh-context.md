# 正式記録の読み書き

現在情報を把握する入口は `company-data/ledger.md` の1か所。最新の最有力情報を記載し、情報がない項目は空欄とする。状態区分・履歴・経緯は持たせない。

## 読むタイミング

Codex・Claude Codeとも、S・開始・再開時にリポジトリ内で次を実行し、出力された台帳全文を読む。

```bash
python3 system/scripts/read-ledger.py
```

最新mainの台帳だけを取得して全文を出力する。Gitは最新版の取得に使い、履歴は読まない。引継ぎノート・原本・他のデータはこのコマンドでは読まない。

`LEDGER_BEGIN` と同じsha256の `LEDGER_END` が見えることを確認する。出力が途中で切れた場合は全文を分割して読む。取得失敗・台帳欠落の場合は読込済みと扱わず、失敗を報告する。古いキャッシュへの自動切替はしない。

会話中の回答・編集ごとには再読しない。台帳の更新を認識した時、または会話の要約などで台帳全文がコンテキストから失われた時に再読する。経緯・原本・引継ぎは必要な時だけ読む。

この仕組みはコマンドによる全文出力と両エージェントへの必須手順であり、モデルの理解や手順遵守を機械的に保証するものではない。

## 書くタイミング

1. 人間から台帳の更新指示を受ける。
2. 作業ブランチの台帳を更新する。対象の値を最新情報に置き換え、情報がなくなる項目は空欄にする。
3. 変更を確認し、commit・pushする。作業ブランチの記載は共通正式記録にはまだ反映されない。
4. 人間のマージ承認によりmainへ反映する。この時点で全員が読む共通版が更新される。
5. 更新を認識した担当は台帳全文を再読する。

台帳への書き込みは作業中、共通版の更新はマージ時。台帳更新の指示はマージ承認を兼ねない。理由・経緯・出典詳細はcommit・PR・原本側に残し、台帳に状態履歴を追加しない。

未マージ版を検証する場合に限り `python3 system/scripts/read-ledger.py --local` を使う。`LOCAL_PREVIEW` は共通版の読込成功とは扱わない。

既存の `sync-context.py` はフォルダのコード・資料や引継ぎを詳しく調べる時の補助として残す。通常の開始時に実行する必須コマンドではない。
