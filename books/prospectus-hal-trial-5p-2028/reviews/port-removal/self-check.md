# スクリーンショットによるセルフチェック

ユーザー指示：港の絵をストックから削除し、スクショでセルフチェックする。

## 検査方法

統合担当自身が既存Chromiumを起動し、合成HTMLの全5ページをPlaywrightのlocator.screenshotで撮影した。printメディア、deviceScaleFactor 1.25。`before/` と `after/` に全5枚と撮影情報を保存。afterの表紙・2–3・4–5のパネルもスクショから合成した。画像を実際に開いて確認し、制作コードや検査ログだけで代用していない。

## 除去結果

- `backgrounds/seaside-watercolor-example.png` と制作ストック内の生成指示を削除。
- `/workspace/generated_images/exec-3945bdb0-a50e-4ca1-ab1a-eb6b892d183b.png` の元生成ファイルも削除。
- p3の画像参照・海辺/夕日/水彩の入力例を除去。学校の実写真と一般的な仕組み図解へ変更。
- 旧紙面は検証履歴として保存。港画像を素材や切り出し元として再利用しない。

## 自分で見つけた問題

| 面 | スクショで見たこと | 判断 |
| --- | --- | --- |
| 表紙 | 女性の顔が主役で、巨大AIは身体に重なる。年度と学校名が読める | この主従は維持 |
| p2 | 総合ビジネス科の「科」だけが次行に残る | 改行の調整が必要 |
| p3・変更前 | 港が学校実写真より大きく主役となり、学校の学びとの接続が弱い | 素材選定と前回の提出判断が甘かった |
| p3・除去直後 | 巨大「活かす。」が翻訳AIを覆う | 位置を修正しafterで再確認、欠損解消 |
| p3・変更後 | 港は消えたが、仕組み図は工程名と矢印に留まり、入力と画像結果の対応を見せていない。上半部右側も主題に対応する群を持たない | 削除完了を紙面品質の合格にしない |
| p2/p3/p5 | 手元写真がp2とp3、学習写真がp3とp5で繰り返され、各面の内容を区別する役割が弱い | 写真の役割と説明の対応を再編集する必要 |
| p4 | 5分野が大小の語の縦列で、文字の大小と意味・写真の対応を示していない | 巨大文字にしただけで学びの具体化を達成したとはいえない |
| p5 | 2027参考・2028未確定・別途実費・相談先を本文で確認。文字切れを目視で検出しない | 費用条件は保持 |

p2とp4のグループ活動は同場面の別カットであり、同一画像とは区別する。

## 結論

港の素材削除と紙面からの除去は完了。文字干渉の局所欠陥も修正した。冊子全体のデザインは差し戻し。前回の「提出可」を今版へ流用しない。残る課題は余白量の一律調整ではなく、主題・写真・図解・説明の対応。本依頼は削除とセルフチェックであり、別の無関係な絵の生成や冊子全面の再制作を勝手に追加していない。
