- 全件評価：`references/research/prompt-evaluation-20261012/`。4視点の全文比較と統合結果。原文と評価は別ファイル。
- 共通型：`system/prompts/agent-role-template.md`。

- 最初の候補：このフォルダの `v1/`。
- 実行する候補の選択設定：`selection.json`。役割ごとの候補、戻せる旧設定、参照原文のパスとSHAを指定する。学校情報の台帳ではない。
- 実行設定：`.codex/roles/*.toml`。Claude用は `sync-dtp-agent-configs.py` で生成する。

今回の選出で他候補を削除しない。原文の要約で原文を置き換えない。技術資料の除外は過去の人間の明示指示によるもので、今回追加で除外したものはない。

## 運用

1. 原文と取得元・ライセンス・SHAを保存した状態で候補を比較する。原文を改善案で上書きしない。
2. 有望な候補の方法を共通型へ具体的に当てはめる。出典、使う部分、冊子向けの変更、適用範囲を残す。
3. 候補を `v2/` など新しいフォルダへ保存する。`baseline/` と過去の候補は上書き・削除しない。役割を一つずつ差し替えてよい。
4. 対象役割の候補TOMLを `.codex/roles/` の対応ファイルへコピーし、`selection.json` の同じ役割の `selected_variant` と参照元を更新する。選択設定と実行設定を同じ変更で揃える。
5. `python3 system/scripts/sync-dtp-agent-configs.py` と `--check` を実行する。Claude側の生成ファイルを別に編集しない。
6. 新規起動するエージェントへ設定全文を渡す。既存セッションに自動適用されたとは扱わない。ホストが登録役割を選択できない場合の対応は `official-configuration.md` に従う。
7. 共通型の登録前検証に従い、実際の紙面、既知の欠陥を含む紙面、良い紙面、情報不足・矛盾の例で試す。期待する結論で評価を誘導しない。
8. 効果が不十分なら、どの手順・判定が機能しなかったかを紙面と結びつけて記録し、候補を修正するか別候補へ交換する。合わなかった候補も保存する。
9. 検証記録は対象BOOKの `reviews/` に、再開位置は引継ぎ台帳に、変更理由は経緯台帳に残す。候補設定を別の現在情報台帳にしない。
10. commit・pushして共有する。mainへの反映は人間のマージ指示で行う。

## 戻し方

`selection.json` の対象役割に指定された `fallback_variant`、または過去の検証済み候補を実行設定へコピーする。選択設定を更新してClaude用を再生成・同期確認し、新しいエージェントを起動する。Git履歴を読まなくても保存済みファイルから戻せる。

v1は最初の候補であり、実紙面での効果は未検証。構文や同期の成功を紙面品質の合格に読み替えない。
