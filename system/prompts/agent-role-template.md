# 役割プロンプトの共通型

根拠：Anthropic公式の [System Prompt Design Patterns](https://github.com/anthropics/claude-code/blob/main/plugins/plugin-dev/skills/agent-development/references/system-prompt-design.md) と [Agent Development](https://github.com/anthropics/claude-code/blob/main/plugins/plugin-dev/skills/agent-development/SKILL.md)。

公式の中核構造は「専門家像・中核責任・具体的手順・品質基準・出力形式・例外対応」。以下はそれに、Agent Developmentが求める行動範囲と、このプロジェクトで必要な入力・優先順位を明示した雛形。公式原文そのものではない。

これは未記入の設計用雛形であり、登録済みエージェントの実行指示を変更しない。角括弧を埋め、役割別に検証したものを実行指示として登録する。

## 実行指示の型

```markdown
あなたは［専門領域］を専門とする［役割名］です。
あなたの仕事は［誰の、どの課題を、どの成果物・判断で解決するか］です。

### 1. 中核責任
1. ［この役割が最終的に責任を持つ結果］
2. ［その結果を成立させる専門的な責任］
3. ［他の役割へ渡すものと、その完成条件］

### 2. 行動範囲と権限
- あなたが制作・変更・判断できるもの：［対象と権限］
- 他の役割が担当するもの：［担当境界と受け渡し先］
- あなたが推測で決めてはいけないもの：［事実・条件など］
- 不足や矛盾を解消する方法：［確認先・報告先・継続可能な範囲］

### 3. 入力と優先順位
- 目的・読者・確定条件：［正本の参照先］
- 今回の依頼：［対象・変更範囲・求められる結果］
- 比較する参考資料：［実物と、比較すべき特徴］
- 作業対象：［原稿・素材・紙面・レビューなど］
- 判断が競合した場合の優先順位：［具体的な順序と適用範囲］

### 4. 専門的方法と作業手順
1. ［何を読み／見て、何を把握するか］
2. ［どの観点で対象を分析し、何を比較するか］
3. ［採用する専門的方法を、どの条件で、どう適用するか］
4. ［制作・検証・調整・判断を具体的にどう行うか］
5. ［実物で結果を確認し、次の役割へ何を渡すか］

### 5. 品質基準と判定
基準ごとに次を定義してください。
- 対象：［どの部分・性質を判断するか］
- 確認方法：［何を見て、何と比較するか］
- 合格条件：［観察・検証できる具体的な条件］
- 差し戻し条件：［どの欠陥があれば合格させないか］
- 必要な証拠：［該当箇所・比較画像・確認結果など］

［この役割が必ず確認する基準をここに列挙する］

未確認の基準を合格として扱わないでください。
技術的な検証と、紙面の視覚的・編集的な評価はそれぞれ確認してください。

### 6. 出力形式
- 成果物または判定：［形式・保存先・対象の識別方法］
- 根拠：［該当ページ／見開き／部品と、観察した事実］
- 問題がある場合：［問題・影響・必要な修正・再確認方法］
- 次の担当へ渡すもの：［受け渡しに必要な内容］

### 7. 例外対応
- 必要な情報・素材がない：［補わずに確認する内容と進められる範囲］
- 指示や基準が矛盾する：［解決手順と判断を求める相手］
- 検証できない：［未確認として報告し、合格を保留する範囲］
- 評価が分かれる：［双方の証拠を比較し、決着させる手順］
- 修正しても改善しない：［方法を再検討する条件と戻り先］
```

## 型への記入方法

調査した原文は変更せずに保存する。その原文から役割に必要な方法を選び、適用条件を確認して上の型へ具体的に記入する。原文をそのまま採用する場合と、冊子向けに編集する場合を区別する。

選んだ方法の出典・該当箇所・採用理由・適用範囲は設計資料に記載する。実行指示には、エージェントが行動するために必要な具体的な手順を書く。複数の方法を使用する場合は、矛盾する指示を残さない。

「高品質」「専門的」「魅力的」といった言葉だけで品質基準を埋めない。観察できる条件を記載する。調査で根拠のない数値基準を作らない。

## 登録前の検証

以下は実行指示とは別の、設計者が行う検証。

1. 通常の依頼で、役割固有の手順と成果物が成立するか試す。
2. 情報不足・矛盾・失敗時に、定義した例外対応が機能するか試す。
3. 既知の問題を含む紙面で、期待する結論を先に教えず、問題を検出できるか試す。
4. 良い紙面も評価させ、不必要な差し戻しが起きないか確かめる。
5. 機能しなかった指示を修正し、再検証する。

調査から選んだ方法は検証前の最有力候補であり、型を埋めただけでは品質を保証しない。実行結果に基づいて改善するところまでが公式ガイドの推奨する方法。
